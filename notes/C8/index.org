The =!$parseYaml= tag parses a YAML string inside a template. In
=src/Iidy/Yaml/Resolver.hs= (around lines 836-843) the parsed AST goes
through =astToValueRaw :: YamlAst -> Value=, an aeson =Value= whose object
keys are held in aeson's =KeyMap=, which may not keep document order. The
Rust original parses with the order-preserving =serde_yaml_ng=, so mapping
keys come out in source order there. If the Haskell result reorders keys,
rendered templates differ from Rust. Flagged in the March Gemini review of
the resolver error paths and confirmed as still present by the C2 triage
([[file:../C2/report--handoff-triage.org][report]]).
