Found by the C40 review (2026-11-17), pre-existing in both originals. The
=CommandsBefore= bash helper functions =iidy_filehash= and
=iidy_filehash_base64= run =shasum -p -a 256 "$1"=
(Rust =~/src/iidy/src/cfn/stack_args.rs:621= and =:625=; iidy-js
=~/src/iidy-js/src/cfn/runCommandSet.ts:33-34=; iidy-hs copies them byte
for byte since C40). Perl =shasum= 6.x removed =-p= (portable mode): on
this host =shasum --version= is 6.04 and =shasum -p -a 256 FILE= prints
"Unknown option: p", so a command that calls either helper fails.
=iidy_s3_upload= does not use them. Without =-p= the digest is the same
for a regular file (portable mode only changed line-ending handling in
text mode).

Parity question for Tavis: both originals share the bug, so the default
parity rule says keep it; the recommendation is to drop =-p= (or use
=sha256sum= with a =shasum= fallback) and record the divergence, because a
helper that cannot run on a current system has no behaviour worth keeping.
