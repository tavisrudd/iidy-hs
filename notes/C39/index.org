C34 (landed) added =parseYamlStrict= in =src/Iidy/Yaml/Parser.hs= and the
key-identity rules in =src/Iidy/Yaml/DuplicateKeys.hs=; imported documents
(=Imports/ContentParsing.hs=) and =!$parseYaml= strings
(=Resolution/Resolver.hs= line 843) use it and reject a repeated mapping key
at any depth. Top-level templates and stack-args still use the lenient
=parseYaml=, so iidy-hs renders both entries of a repeated key
(=DIVERGENCES.md= "Duplicate Mapping Keys: Error Text" says both ports
accept it at top level; that is no longer true for TypeScript, see below).
Rust accepts a repeated key at top level (last value wins); TypeScript
(js-yaml) rejects it.

Decision (Tavis, 2026-11-16): reject a repeated mapping key in top-level
templates and stack-args too, as TypeScript (js-yaml) does, with the same
message format as for imports. Rust's behaviour (accept, last wins) becomes
a recorded divergence.

Call sites of the lenient =parseYaml=, verified 2026-11-16 with
=grep -rn parseYaml src app=:
- Switch to =parseYamlStrict= (top-level user documents):
  =src/Iidy/Cfn/StackArgsLoader.hs= line 166 (stack-args file);
  =src/Iidy/Cfn/TemplateLoader.hs= line 112 (a =render:= template);
  =src/Iidy/Render.hs= line 80 (the =render= command's input template).
- Stay lenient, because the text was already parsed strictly when it was
  imported and a second strict pass adds nothing but cost:
  =src/Iidy/Yaml/Engine.hs= line 273 (re-parse of an imported document that
  has imports or defs; =ContentParsing.hs= has already rejected duplicates,
  and a failed re-parse falls back to the raw value);
  =src/Iidy/Yaml/Resolution/Resolver.hs= line 323 (=buildReparse=) and line
  887 (=!$expand=), which re-parse =tiRawBody=, set from an imported
  document's raw text at =Engine.hs= line 221 and so already checked.
  Verify the claim for =tiRawBody= when starting: if any path builds it
  from text that did not pass =parseYamlStrict=, stop and record it.
- Strictness unclear, goes to the supervisor before any change (stop rule):
  =src/Iidy/Demo.hs= line 81 (a demo script is a top-level user document
  but is neither a template nor stack-args; TypeScript's demo loads it with
  js-yaml, which would reject); =src/Iidy/Cfn/Operations/ConvertStack.hs=
  line 191 (=templateBodyToYaml=, which parses a template body fetched from
  AWS for =convert-stack-to-iidy=: rejecting would make a stack
  unconvertible rather than flag the user's own mistake). Until the
  supervisor answers, leave both lenient.
  Decision (Tavis, 2026-11-17): =Demo.hs= switches to =parseYamlStrict=
  (demo scripts reject a repeated key, as TypeScript does);
  =ConvertStack.hs= stays lenient, because that text comes from AWS.
- Not a call site of concern: =parseYamlFile= (=Parser.hs= line 55) has no
  caller in =src/= or =app/=; leave it or remove it only if it stays
