Cause: =renderNewStackEvents= stopped the spinner, printed the events, then
called =startSpinner r "Loading live events..."=; the timing thread only
replaced that text after its first 1s sleep, so the placeholder flashed in
default colour after every batch. It also briefly reset the timing start time
before the caller overwrote it.

Fix: =resumePollingSpinner r startTime mLastEventTime= (Types.hs) starts the
spinner with the muted timing message already computed and seeds the timing
state directly (no reset window). =startSpinner= and it share
=startSpinnerWithTiming=; =timingMessage= is shared with =timingLoop=. The last
event time falls back to the previous one when the batch has no timestamps.

Rust parity: the Rust implementation has the same flash
(=~/src/iidy/src/output/renderers/interactive.rs= =render_new_stack_events=,
which calls =create_api_spinner("Loading live events...")= before
=start_live_events_timing=). Tavis wants Rust to behave the same way, but
=~/src/iidy= is read-only from iidy-hs sessions; the matching Rust change is to
create the restarted spinner with the formatted timing text
(=format!("{total} seconds elapsed total. {since} since last event.")=, muted)
instead of the placeholder, and to set the last event time before the first
timing tick.
