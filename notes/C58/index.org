=describe-stack= on c109-operator-role (updated with a changeset) showed
=CREATE_FAILED= for the stack where the console shows
=UPDATE_COMPLETE_CLEANUP_IN_PROGRESS=. =Iidy.Cfn.Status= had no constructor
for the two =*_CLEANUP_IN_PROGRESS= stack statuses (or resource
=IMPORT_FAILED=), and =fromCfnStackStatus= / =fromCfnResourceStatus= fell
back to =CreateFailed= for any text they did not know. Stack events carry
the stack's own status in their resource status, so every update that
needs cleanup hit the fallback.

Beyond display: =CreateFailed= is terminal and failed, so the poll in
=update-stack=, =exec-changeset= and =watch-stack= could stop at the
cleanup event and report the update as failed. Rust and iidy-js both list
both cleanup statuses as in progress (=src/output/status.rs=,
=src/cfn/statusTypes.ts=).
