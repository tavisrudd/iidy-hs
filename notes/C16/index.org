Template approval lets a reviewer approve a pending template, which is then
stored as an approved object in S3; the stack-args setting
=ApprovedTemplateLocation= names where approved templates live. The C4
review found that create, update and changeset
(=src/Iidy/Cfn/RequestBuilder.hs= around lines 69, 110 and 159) send the
local template regardless of approval, so approval is advisory only. Also,
when the review step finds no difference it reports "approved" without
writing the approved object (=src/Iidy/Cfn/TemplateApproval.hs= around line
226). The Rust port has the same gap. See
[[id:org:01a1e68e-1585-707c-91d5-94cde3b60847][Medium: ApprovedTemplateLocation is not enforced]].

The user wants this to start from what the original TypeScript iidy
(=~/src/iidy-js=, read-only) intended and does, and to discuss the design
before any change. Starting points there: =src/cfn/approval/index.ts=,
=src/cfn/AbstractCloudFormationStackCommand.ts=, =src/cfn/loadStackArgs.ts=.

Follow the TypeScript original (option A of the report).

- Deploy from the approved S3 object's URL, presigned as iidy-js does, for
  create-stack, update-stack and create-changeset, and so for every command
  that goes through them (create-or-update, =update-stack --changeset=),
  and for estimate-cost.
- Check the approved object exists (=HeadObject=) before any CloudFormation
  call and refuse with a message telling the user to run
  =template-approval request=.
- =template-approval review= with an empty diff prompts and, on yes, writes
  the approved object as iidy-js does; the ports' no-diff shortcut goes.
- Refuse when =Template= is itself a URL and approval is on.
- Fix the request-side gaps: honour the lint flag, and upload the pending
  object with the =bucket-owner-full-control= ACL.

Hash: keep SHA256 (supervisor's call, following the report's
recommendation that Tavis accepted); record the difference from the iidy-js
MD5 keys in =DIVERGENCES.md=. Lint: lint the local rendered body when
approval is on (supervisor's call, same basis).

** User-visible changes (for the docs task)
:PROPERTIES:
:ID: org:01a1e6fd-8bb4-76f0-af12-17f2a48b31c1
:ADDED: [2026-11-16 Mon 17:52]

- With =ApprovedTemplateLocation= set (and not disabled by
  =/iidy/disable-template-approval=), create-stack, update-stack (direct
  and =--changeset=), create-changeset, create-or-update and estimate-cost
  send a presigned =TemplateURL= for the approved object (15-minute expiry,
  the AWS SDK default iidy-js relied on) instead of the local body.
- The deploying principal needs =s3:GetObject= on the approved keys (the
  URL is signed with its credentials); an IAM
  =cloudformation:TemplateUrl= condition on the deploy role now works.
- Unapproved templates are refused before any CloudFormation call, with
  "not approved, run =iidy-hs template-approval request <argsfile>="; a 403
  gets its own "no permission to read the approved template" message.
- A =Template= given as an =s3://= or HTTP(S) URL is refused when approval
  is on, by request and by every deploy command.
- Templates approved by iidy-js (MD5 keys) are not found by iidy-hs (SHA256
  keys) and must be approved again.
- =template-approval review= always prompts, even with an empty diff; yes
  writes the approved and =latest= objects and deletes the pending one.
- =template-approval request= validates the rendered template with
  =ValidateTemplate= before upload unless =--no-lint-template= is given,
  and exits 1 without uploading on errors; the pending object is uploaded
  with =bucket-owner-full-control=; a =HeadObject= error other than "not
  found" now fails the command instead of being read as "not approved".
