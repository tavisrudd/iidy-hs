The output renderer's width comes from =detectCapabilities= in
=src/Iidy/Output/Terminal.hs= (lines 18-41), which reads only the =COLUMNS=
environment variable. When =COLUMNS= is unset or invalid it gives
=Just 80= on a terminal and =Nothing= otherwise. =COLUMNS= is usually not
exported to child processes, so in practice output wraps at 80 on wide
terminals. The consumer is =newInteractiveRendererWithHandles= in
=src/Iidy/Output/Renderers/Interactive/Types.hs= (line 176), which uses
=tcWidth= and falls back to =defaultScreenWidth= (130, line 112) when it is
=Nothing=; =src/Iidy/Output/Manager.hs= line 90 also passes =tcWidth= on.

The Rust original does not read =COLUMNS= at all. It has two places:
=TerminalCapabilities::detect_terminal_width= in
=~/src/iidy/src/output/terminal.rs= (line 54, the real size via the
=terminal_size= crate, else =None=) and =get_terminal_width= in
=~/src/iidy/src/output/theme.rs= (line 177, the real size, else 130, used by
the interactive renderer at =renderers/interactive.rs= line 101). So Rust's
order is: real terminal size, then 130. The =terminal-size= package is
already a dependency (=iidy-hs.cabal= line 122) and is used in
=src/Iidy/Cli/Help.hs= (=size=, around line 195). Flagged in the March
Gemini review of the interactive renderer; still present per the C2 triage
([[file:../C2/report--handoff-triage.org][report]]).

C18 also works in =src/Iidy/Output/=; this card stays inside
=Terminal.hs= (the renderer files above are read, not edited).

Correctness notes:
- Handle: =TermSize.size= queries stdout; the renderer's =tcIsTty= is also
  =hIsTerminalDevice stdout= and the interactive renderer writes to stdout
  (spinner/status to stderr only when stdout is a tty). Rust's
  =terminal_size()= tries stdout, then stderr, then stdin. With stdout
  redirected Haskell gives =Nothing= (130) while Rust could pick up a
  stderr tty; Rust's =is_terminal= check on stdout makes the renderer
  non-interactive in that case, so no visible difference.
- Redirected stdout: =realSize= is not queried, =Nothing=, same as before.
- Fallback: Manager.hs:90 passes =tcWidth caps= as =ioTerminalWidth=;
  Interactive/Types.hs:176 gives =fromMaybe (fromMaybe 130 (tcWidth caps))
  (ioTerminalWidth opts)=, so =Nothing= yields 130 as Rust's theme.rs:177.
- No duplication: =COLUMNS= parsing stays in one place; test module is its
  own file and is registered in cabal and Main.hs.

Defects:
1. Low, Terminal.hs =parseColumns=: =reads= on =Int= wraps on overflow, so
   =COLUMNS=18446744073709551716= parses as 100 and a value just above
   =maxBound= becomes a huge or negative number (negative falls through).
   Pre-existing logic, not introduced here. Fix: parse via =Integer= and
   cap or reject above a sane bound. No test covers it.
2. Low, Terminal.hs =detectCapabilitiesWith=: a size query returning
   =Just 0= (some ptys report 0x0) becomes =tcWidth = Just 0= and the
   renderer gets width 0, not 130. Rust has the same shape
   (=Some(0)=), so parity holds, but the card text says zero should fall
   through. Fix: =filter (> 0)= on the real size in =resolveWidth=, plus a
   test.
3. Low, DIVERGENCES.md: entry is accurate but does not note that the stdout
   only query differs from Rust's stdout/stderr/stdin order. Optional.
