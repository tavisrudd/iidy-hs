The output renderer's width comes from =detectCapabilities= in
=src/Iidy/Output/Terminal.hs= (lines 18-41), which reads only the =COLUMNS=
environment variable. When =COLUMNS= is unset or invalid it gives
=Just 80= on a terminal and =Nothing= otherwise. =COLUMNS= is usually not
exported to child processes, so in practice output wraps at 80 on wide
terminals. The consumer is =newInteractiveRendererWithHandles= in
=src/Iidy/Output/Renderers/Interactive/Types.hs= (line 176), which uses
=tcWidth= and falls back to =defaultScreenWidth= (130, line 112) when it is
=Nothing=; =src/Iidy/Output/Manager.hs= line 90 also passes =tcWidth= on.

The Rust original does not read =COLUMNS= at all. It has two places:
=TerminalCapabilities::detect_terminal_width= in
=~/src/iidy/src/output/terminal.rs= (line 54, the real size via the
=terminal_size= crate, else =None=) and =get_terminal_width= in
=~/src/iidy/src/output/theme.rs= (line 177, the real size, else 130, used by
the interactive renderer at =renderers/interactive.rs= line 101). So Rust's
order is: real terminal size, then 130. The =terminal-size= package is
already a dependency (=iidy-hs.cabal= line 122) and is used in
=src/Iidy/Cli/Help.hs= (=size=, around line 195). Flagged in the March
Gemini review of the interactive renderer; still present per the C2 triage
([[file:../C2/report--handoff-triage.org][report]]).

C18 also works in =src/Iidy/Output/=; this card stays inside
=Terminal.hs= (the renderer files above are read, not edited).
