A =Template:= value that is a local path to a file that does not exist is
used as the template body. In =src/Iidy/Cfn/TemplateLoader.hs=,
=loadCfnTemplate= (the local-path guard, about line 95) calls
=doesFileExist= on the resolved path (line 98); when it is false the
else branch (lines 120-131) treats the value as "might be inline content"
and returns it as =TemplateBody= (line 131). A typo such as
=Template: templats/app.yaml= therefore yields a one-line body, and
=template-approval request= uploads it (found in the C16 review, P2). The
existing test =missing file treated as inline content (not an error)= in
=test/Test/TemplateLoaderTest.hs= (line 306) pins this behaviour and must
change.

What the originals do:
- Rust (=~/src/iidy/src/cfn/template_loader.rs:57-61=): =is_inline_content=
  is true when the trimmed text starts with ={= or =[=, contains a newline,
  or is under 260 bytes with no =/= and no =\=. It is decided before any
  file check, and inline content is used verbatim (lines 79-83). So in Rust
  =Template: template.yaml= (existing file, no slash) is taken as the body
  =template.yaml=, a likely accident rather than a design. Any other value
  goes to =load_file_import=, which fails with "Failed to load template
  from: PATH" (line 85-87). Recorded by code reading only: no Rust command
  loads a template without reaching AWS, so it was not run. A test for
  inline JSON exists (=tests/template_loading_integration_tests.rs:185=);
  none covers a short bare word.
- TypeScript (=~/src/iidy-js/src/cfn/loadCFNTemplate.ts:34-37=): there is no
  inline content. Every non-URL value goes to =readFromImportLocation=
  (=src/preprocess/index.ts:452=), whose =parseImportType= (line 184)
  treats a value without =:= as a file; a missing file throws an
  =ImportError= with the read error, and a value containing =:= that is not
  a known scheme throws "Unknown import type".

Proposed rule: keep inline content only for text that cannot be a path:
starts with ={= or =[= (after trimming) or contains a newline. Everything
else is a file path, and a missing file is an error naming the resolved
path. This keeps Rust's real inline cases, matches TypeScript for paths,
and drops only Rust's "short and slashless" accident (which also makes an
existing =template.yaml= work, as it does today in iidy-hs).
