Found 2026-11-17 while rescoping [[file:../C35/index.org][C35]]. The Rust
YAML parser decodes only =\n=, =\t=, =\r=, =\\=, =\"=, =\'= and =\0= in a
double-quoted scalar (=unescape_string=,
=~/src/iidy/src/yaml/parsing/parser.rs:1763-1792=). Every other escape is
kept as literal text: an unknown escape pushes the backslash and the
character. So =render= changes values silently. Recorded 2026-11-17 with
=~/src/iidy/target/debug/iidy render= on local files:

| input           | Rust render       | correct value (iidy-hs render) |
|-----------------+-------------------+--------------------------------|
| ="\x41"=        | =\x41=            | =A=                            |
| ="B"=      | =B=          | =B=                            |
| ="\e"=          | =\e=              | ESC (U+001B)                   |
| ="x\ay"=        | =x\ay=            | =x=, BEL (U+0007), =y=         |
| ="a\tb\x01"=    | ='a<TAB>b\x01'=   | =a=, TAB, =b=, U+0001          |

The same holds for =é= and every other =\x=, =\u=, =\U= escape, so
non-ASCII text written as an escape reaches CloudFormation as backslash
text. The parser also accepts =\'=, which YAML 1.2 does not define in a
double-quoted scalar. =get-import= is not affected: it parses with
serde_yaml.

The emitter has a second, smaller problem once the parser is fixed:
=emit_str_iidy= (=~/src/iidy/src/yaml/emitter.rs:396-416=) prefers single
quotes, and =emit_single_quoted_string_iidy= (lines 452-464) writes control
characters raw. A single-quoted scalar cannot hold a non-printable
character, so the output would not be valid YAML. iidy-hs has the same
emitter bug (C35 fixes it there by double-quoting such strings with YAML
escapes); this card makes Rust do the same, so both print the same text.

This card edits the Rust repository, =~/src/iidy/=, which is otherwise
read-only for this project. Tavis authorised that on 2026-11-17 for this
card.
