#+title: C18 untrusted-text sinks in the interactive renderer

Existing-owner search (duplication rule): no function in =src/= escapes or
strips terminal control characters for display. =Iidy.Yaml.Emitter= escapes
control characters inside YAML scalars (its own quoting rules, for YAML
output, not terminal text) and the JSON renderer relies on aeson; neither
fits, so a new pure module =Iidy.Output.Sanitize= is the single owner.
=Iidy.Output.Terminal= is out of scope. Test helpers reused:
=Test.Shared.mkColoredRenderer= / =mkPlainRenderer= (refactored to share one
constructor so a handle-capturing variant can be added).

Routing design: =Interactive.hs= =renderOutputData= applies one pure pass,
=escapeOutputData= (in =Iidy.Output.Sanitize=), to the whole =OutputData=
before any rendering. Every Text field of every record is escaped there, so
colour codes are added to, and widths computed from, the visible text, and
=Sections.hs= needs no per-site calls. The Route column below therefore reads
"escapeOutputData" for every row except the two exemptions.

Context: C18 escapes renderer output only. Errors.hs dieTxt and the ERROR
lines, GetImport/Render/Demo/Explain stderr writes and Params/Review
(current and pending parameter values) print exception or AWS text raw.

=src/Iidy/GetImport.hs=, =src/Iidy/Render.hs=, their tests.
