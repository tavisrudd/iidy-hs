The shared YAML emitter =emitYaml= in =src/Iidy/Yaml/Emitter.hs= indents a
sequence under a mapping key by two spaces (=emitMapValue= at line 210 calls
=emitArray= at line 148 with the key's indent plus two), giving
=  c:\n    - x=. Rust's =serde_yaml= puts the dashes at the key's indent:
=  c:\n  - x=. Found while reviewing C13 (=notes/C13/index.org=, the DONE task
"End YAML output with a newline ...", "Known remaining divergence").

Verified by running both binaries (Rust =~/src/iidy/target/debug/iidy=):
- =get-import= YAML output uses =serde_yaml::to_string=
  (=~/src/iidy/src/cfn/get_import.rs= line 56) and is unindented: the
  Rust result for =a: {c: [x, y]}= is =a:\n  c:\n  - x=. iidy-hs indents.
- =render= YAML output in Rust uses its own emitter
  (=serialize_yaml_iidy_js_compatible=, =~/src/iidy/src/yaml/engine.rs= line
  652, =~/src/iidy/src/yaml/emitter.rs=) which does indent sequences, and
  iidy-hs =render= matched it byte for byte on a nested-sequence sample.
So the parity gap is specific to the places where Rust uses =serde_yaml=:
=get-import=, =!$toYamlString= (=resolver.rs= around line 1781), the
handlebars =toYaml= helper (=helpers/serialization.rs= line 57) and
=param= YAML output (=params/mod.rs= line 234). In iidy-hs, =emitYaml= has
these callers: =Render.hs= lines 101-102 (render, must keep indenting),
=GetImport.hs= lines 131-132, =Cfn/TemplateLoader.hs= line 90,
=Yaml/Handlebars/Helpers.hs= line 288 and =Yaml/Resolution/Resolver.hs=
line 834 (=!$toYamlString=). =src/Iidy/Params/Client.hs= has a separate
emitter (=renderYaml=, line 279, documented as serde_yaml-compatible) that
also indents sequences under keys. Existing tests of the emitter:
=test/Test/EmitterTest.hs=, =test/Test/CfnYamlEmitterTest.hs=; fixtures
under =test-fixtures/= avoid nested sequences in get-import output.

Changing =emitYaml= itself would change =render= output, which already
matches Rust, so it must not be done blindly. Depends on C13 for the
=GetImport.hs= call sites (C13 is editing that file); start after it lands.
