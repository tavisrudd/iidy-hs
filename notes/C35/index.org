Rust is no reference here. Its parser keeps =\x=, =\u=, =\e=, =\a= and
other escapes as literal text, so its =render= prints ='a<TAB>b\x01'= with
four literal characters: valid YAML, wrong value. That is filed as
[[file:../C42/index.org][C42]] (fix Rust). Rust =get-import= (serde_yaml)
prints ="a\tb\x01"=. Rust and iidy-hs should end up printing the same
text; C42 takes its escape spelling from this card.

Floats are out (Tavis, 2026-11-17): =render= prints =1.0= as =1= as Rust

Escape spelling for C42 (YAML double-quoted scalar): =\"= and =\\= as
usual; =\0= NUL, =\a= BEL, =\b= BS, =\t= TAB, =\n= LF, =\v= VT, =\f= FF,
=\r= CR, =\e= ESC, =\N= U+0085, =\L= U+2028, =\P= U+2029; any other
non-printable below U+0100 (C0, DEL, C1) as =\xHH=, and anything above
(U+FEFF) as =\uHHHH=, hex digits upper case (serde_yaml's spelling, for
example =\x7F=). Triggers: C0 controls except TAB and LF, DEL, U+0080-U+009F,
U+2028, U+2029, U+FEFF. A string with only TAB keeps its single-quoted form.
A multi-line string with such a character is also double-quoted (a block
scalar cannot hold it). Mapping keys follow the same rule.

Why this differs from C18's =\uNNNN= lower-case form: C18 is terminal
display, where every control becomes a visible =\uNNNN= and nothing needs to
be parsed back. YAML has its own escape grammar (short escapes, =\x= form,
upper-case hex) that a YAML parser must read back to the same value, so the
YAML emitter has its own function and C18's is not reused.

Implementation: the emitter's single string path =emitStringAt= (used for
root, mapping values, sequence items and tag arguments) plus =emitMapKey=
route to the existing =escapeDoubleQuotes=, which was extended with the
escapes above. Blank-line bug: =emitMappingInline= and =emitArrayInline=
appended a newline after a lone first entry; they now join first and rest in
one =intercalate=. This also removes the blank after any single-key mapping
or single-item sequence inside a sequence.

Tests (=test/Test/EmitterTest.hs=) were written first and run on the base:
23 failed (every character class, each of the key, value, sequence element,
tag argument and multi-line cases, the SeqFlush round trip, and the tag
blank line). Each class also round-trips through =parseYamlOrdered=
(iidy-hs's own parser) to the same value. Fixture expected outputs changed:
none. Full suite on the rebased tip 9d44d62: all 2217 tests pass (see
commit hook and final run).

1. Floats need the parser. =Scientific= cannot tell =1.0= from =1=:
   =Iidy.Yaml.Parser.parseFloat= builds =Sci.fromFloatDigits 1.0=, which is
   the same value (coefficient 1, exponent 0) as =fromInteger 1=. Same in
   =Imports/ContentParsing.hs= (=NumDecimal=). The emitter alone cannot print
   =1.0=. That is the card's stop rule (parser must keep float-ness). Also
   =parseFloat= feeds =.inf=/=.nan= through =fromFloatDigits=, which cannot
   represent them, so =.inf=, =-.inf=, =.nan= need a new representation too.

2. The card's Rust outputs belong to =get-import= (serde_yaml) only.
   =render= (Rust iidy-js-compatible emitter) differs. Recorded from
   =~/src/iidy/target/debug/iidy= on a local file:

| input        | get-import (serde_yaml) | render                    |
|--------------+-------------------------+---------------------------|

| -0.0         | -0.0                    | -0                        |

So render already prints =1= for =1.0= (iidy-hs matches); only get-import

command (get-import uses YAML escapes =\N=, =\e=, =\0=, =\b=, =\f=, =\v=,
=\a=, =﻿=; render emits odd unquoted/single-quoted text with literal
backslash escapes). The emitter has one scalar path shared by both.

Decisions needed: (a) allow a parser/number-representation change (outside the
allowed paths) so get-import can print =1.0=, and how to represent =.inf=;
(b) whether the control-character fix targets get-import only (keyed on
=SeqFlush= or a new style parameter) and whether render's odd output should
also be copied. Not run: iidy-hs itself (no build made yet).
