Two functions pretty-print JSON by wrapping aeson-pretty's
=encodePretty= and differ only in indent width:
=formatJsonPretty= in =src/Iidy/GetImport.hs= (two spaces plus a trailing
newline, using =encodePretty'= with =confIndent = Spaces 2=) and
=formatJson= in =src/Iidy/Render.hs= (line 144, the aeson-pretty default of
four spaces, no trailing newline, used at line 100 for =RenderJson=). The
C13 review (=notes/C13/index.org=, the "Review 2026-11-16" heading, defect 1)
proposed one shared helper taking the indent. Other pretty-JSON callers
exist (=src/Iidy/Output/Renderers/Json.hs= lines 161 and 174,
=src/Iidy/Yaml/Handlebars/Helpers.hs= line 283,
=src/Iidy/Cfn/Operations/ConvertStack.hs= line 568,
=src/Iidy/Params/Client.hs= line 264 with its own two-space config); they
are not part of this card.

Dependency: C13 is changing =src/Iidy/GetImport.hs= and introduces
=formatJsonPretty= (it exists only on the C13 branch at the time of
writing, line 154 there; on =main= the file does not have it yet). Do not
start this card until C13 has landed on =main=, then re-check the line
numbers.

Finding for Tavis: Rust's =render --format json= uses
=serde_json::to_string_pretty= (=~/src/iidy/src/render.rs= line 44), which
is two-space; running both binaries on the same input shows Rust two-space
and iidy-hs =render= four-space. So Render's four-space output is itself a
divergence from Rust.

Decision (Tavis, 2026-11-16): switch =render --format json= to two-space,
matching Rust. Both commands then use the same two-space layout, so the
shared helper needs no indent parameter.
