Found by the C58 audit ([[file:../C58/report--related-status-audit.org]]).
=pollForCompletionWith= (=src/Iidy/Cfn/StackOperations.hs=) ignored stack
events older than the operation's start time only for =watch-stack=
(=pcWaitForStatusChange=). For create, update, exec-changeset and delete,
a poll that ran before CloudFormation wrote the new operation's first
event saw the previous operation's terminal stack event (for example the
last update's =UPDATE_COMPLETE=) as newest and returned it at once, so the
command could report the old result without waiting. =exec-changeset= is
most exposed, since change set execution starts asynchronously. Rust
filters by start time for every operation (=process_new_events= in
=src/cfn/stack_operations.rs=); iidy-js does too (=ev.Timestamp > startTime=).
The filter was limited to watch-stack in 2409809 (2026-03-03) as a
watch-stack fix, with no reason recorded for leaving write operations out.
