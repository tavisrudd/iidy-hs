Decision (Tavis, 2026-11-16): give =render= an AWS environment from the
global options, built lazily as =get-import= does (C7), so local-only
templates keep working without credentials. The reasoning is in
[[file:../C23/report--decisions-vs-originals.org][C23's report]] item 9:
TypeScript =renderMain= calls =configureAWS= first (=src/render.ts:31=) and
resolves credentials eagerly (=configureAWS.ts:62-73=), so its =render=
needs credentials even without AWS imports; Rust =render.rs:31-33= calls
=preprocess_yaml= with no AWS config at all. Eager TypeScript behaviour is
not wanted. Origin: an open question left by [[file:../C7/index.org][C7]].

What fails today: =runRender= (=src/Iidy/Render.hs:59=) builds
=ImportConfig{icAwsEnv = Nothing, ...}=. =withAwsEnv=
(=src/Iidy/Yaml/Imports/Loaders/Dispatch.hs:84=) then answers any
=ssm:=, =ssm-path:=, =cfn:= or (with remote imports allowed) =s3:= import
with "AWS import type requires credentials and is not available in this
context". =app/Main.hs:78= calls =runRender= without the AWS settings.

How =get-import= does it (C7, =src/Iidy/GetImport.hs=):
- =runGetImport= (line 54) passes =fst <$> createAwsEnvFromSettings
  awsSettings= to =runGetImportWith= (line 62), which takes an
  =IO Amazonka.Env= provider.
- It decides from the one location with =needsAwsEnv= (line 87), runs the
  provider at most once through =tryBuildEnv= (line 107), which turns
  credential, region and STS failures into one message, and reports
  "Import error: ..." with exit 1.
- =test/Test/GetImportTest.hs= counts builds: =runArgs= (line 51) wraps the
  provider in =bump=, and =rrEnvBuilds= is asserted 0 for file:, env: and
  blocked s3: imports (lazinessTests) and 1 for the mock-backed ssm: and
  cfn: cases (mockAwsTests, using =mockEnv= from =Test.MockAws=).

The difference for =render=: imports are discovered while the template is
resolved, not named up front, so "build only if an AWS import is used"
cannot be decided before preprocessing. The env must be built on first use
inside the import dispatcher, once, and a build failure must surface as an
import error on that import. =ImportConfig.icAwsEnv= is a plain
=Maybe Amazonka.Env= today and has four other constructors:
=src/Iidy/GetImport.hs:77=, =src/Iidy/Cfn/StackArgsLoader.hs:119=,
=src/Iidy/Demo.hs:87= and three in =src/Iidy/Cfn/RequestBuilder.hs=.

Ownership rule: the env-building logic (run the provider once, memoise it,
map =AuthError=, =IOException= and =Amazonka.Error= to the message) has one
owner, shared by =get-import= and =render=. Extract =tryBuildEnv= and the
memoising provider out of =GetImport.hs= (for example next to
=ImportConfig= in =Dispatch.hs=, or a small module beside it); do not copy
them into =Render.hs=. =get-import= may keep its up-front =needsAwsEnv=
check or move onto the same lazy path, as long as its existing tests pass
unedited.

Out of this card: a stack-args file rendered by =render= (C23 item 9 says it
should follow the stack-args AWS rules of item 5); that belongs to
[[file:../C17/index.org][C17]], which owns those rules.
