A stack-args.yaml with

: Parameters:
:   PublicFavicon: "false"
:   SessionTimeout: "300"

loaded =PublicFavicon= as the boolean =false= (C61 is the poor error that
followed). Rust iidy keeps it the string ='false'=.

Cause: stack-args are preprocessed in YAML 1.1 compatibility mode
(=preprocessYamlWithVariables ... True= in
=src/Iidy/Cfn/StackArgsLoader.hs=). After resolution, =convertYaml11CompatO=
(=src/Iidy/Yaml/Engine.hs:335=) turns every string that =isBooleanLike=
(true/false/yes/no/on/off in three casings) into a boolean. It runs on the
resolved value, where plain and quoted scalars are indistinguishable, so
quoted strings are converted too. Reproduce with
=iidy-hs render --yaml-spec 1.1 FILE=: =PublicFavicon: "false"= renders as
=false=; with =--yaml-spec 1.2= it stays ='false'=.

Rust (=convert_yaml_12_to_11_compatibility_with_context=,
=src/yaml/engine.rs:461-551=) differs in two ways: it converts only
yes/no/on/off (=true=/=false= variants are left to the parser, which only
makes plain ones booleans), and =should_preserve_as_string= skips paths
containing Description, Name, Value, Message, Text, Content or Data and
strings longer than five characters. Rust shares the quoting flaw for
quoted ="yes"= / ="no"= etc.

Affects every YAML 1.1 preprocess: stack-args, and templates rendered or
deployed with YAML 1.1 detected (=Iidy.Render=, =shouldUseYaml11Compatibility=).

Options, in order of preference:
1. Spec-correct: apply YAML 1.1 boolean resolution only to plain
   (unquoted) scalars. Needs the scalar style from the parser (HsYAML
   events carry it) to survive into the AST, or do the conversion at parse
   time instead of on the resolved value. Diverges from Rust only for
   quoted yes/no/on/off, where Rust is wrong.
2. Rust parity: drop true/false from =isBooleanLike= and port
   =should_preserve_as_string=. Fixes this report but keeps the quoting
   flaw for quoted yes/no.
Decide with a look at how strings produced by =!$= variables or
handlebars should behave (they have no source quoting).

** Result
:PROPERTIES:
:ID: org:01a1fabe-2d3b-763e-81a7-babfe9f2b1fa
:ADDED: [2026-11-20 Fri 13:55]
:END:
Done the spec-correct way (option 1). YAML 1.1 booleans are a parse-time
schema: =Iidy.Yaml.Parser= gains =BoolSchema= (=Yaml12Bools= /
=Yaml11Bools=) with =parseYamlAs= / =parseYamlStrictAs=; under
=Yaml11Bools= a plain, untagged yes/no/on/off (three casings) is an
=AstBool=, quoted and =!!str= values stay strings, and a mapping key keeps
its text (the loader node carries the source word). =convertYaml11CompatO=
is gone.

Callers that preprocess as YAML 1.1 parse with the matching schema: the
stack-args loader, =render:= templates, demo scripts, and =render= (which
now decides the spec before parsing). The engine carries the schema in
=Importer= and =TagContext= (=tcBools=) for imported documents (re-read
from their text when the loader parsed text and the document holds a
candidate word), =!$parseYaml= strings and custom template bodies.

Differences from Rust are listed in =docs/dev/rust-compatibility.org=
(quoted yes/no stay strings; computed strings and non-text imports are not
converted; no Rust path/length heuristics). Requirements doc
(02-yaml-preprocessing, US-02-008) updated.

Tests: =Test.Yaml11BoolsTest= (parser, preprocess, imports, =!$parseYaml=),
a stack-args loader test with the reported Parameters, and the fixture
=yaml-11-quoted-strings=. The fixture harness now parses with the schema
its preprocess uses (it parsed YAML 1.2 before and relied on the post-pass).
