The project documentation under =docs/= is Markdown: the user docs at the
top level (=README.md=, =getting-started.md=, =command-reference.md=,
=import-types.md=, =yaml-preprocessing.md=, =custom-resource-templates.md=,
=SECURITY.md=), the developer docs and ADRs in =docs/dev/= and
=docs/dev/adr/=, and the requirements set in =docs/requirements/=. Cards
([[file:../C1/index.org][C1]]) are Org, and =c= expands Org links when it builds a
card packet, so docs in Org with =file:= and =id:= links can be linked from
cards and pulled into an agent's context precisely, down to a heading.

No build, test or CI file references =docs/=. Links into =docs/*.md= do
exist in the top-level =README.md=, =WORKPLAN.md=, cross-links between the
requirements docs, and many historical notes under =notes/=.

* Scope and gate

Allowed paths: =docs/=, the top-level =README.md=, =WORKPLAN.md=,
=CLAUDE.md=, =AGENTS.md=, and =notes/C5/=. Historical notes under =notes/=
(handoffs, reviews) are left as they are; their links to old =.md= paths go
stale by design, since [[file:../C2/index.org][C2]] archives them.

Gate: every =.md= file under =docs/= is replaced by an =.org= file of the
same name (=git mv= first, so history follows), with =#+title:=, Org
headings, Org tables, =#+begin_src= blocks with languages, and Org-style
links (=[[file:...][label]]= for files, =[[*Heading][label]]= or =id:= links
for headings, =[[https://...][label]]= for URLs); no Markdown syntax is left
(check with =rg -n '\]\(|^#{1,6} |^```' docs/=); every internal link resolves
to an existing file or heading; links into =docs/= from the allowed
top-level files point at the new =.org= paths; GitHub renders the converted
files. Work committed with C5 in the messages.
