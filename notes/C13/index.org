=iidy get-import <location> [--query EXPR] [--format yaml|json]= loads one
import and prints it. The Haskell port differs from Rust in two ways, found
while working C7 ([[file:../C7/index.org][C7 notes]], "Side findings"):

1. =--query= is parsed into =giaQuery= (=src/Iidy/Cli.hs:315=) but never
   read. =runGetImportWith= in =src/Iidy/GetImport.hs= (call to =emitDoc=
   at line 80) prints the whole document. Rust applies the query before
   formatting: =~/src/iidy/src/cfn/get_import.rs:45-54= calls
   =apply_jmespath_query= and, on error, prints the error to stderr and
   returns exit 1. Haskell already has the pieces: =applyJmesPath :: Text
   -> Value -> Either JMESPathError Value= (=src/Iidy/Yaml/JMESPath.hs:55=)
   and =formatJMESPathQueryError= (=src/Iidy/Errors/JMESPath.hs=), used by
   =render='s =queryStep= (=src/Iidy/Render.hs:89-93=).
2. YAML output has no trailing newline. =emitDoc=
   (=src/Iidy/GetImport.hs:125-132=) emits =emitYaml (fromValue doc)= as
   =OdRawOutput= unchanged. Rust prints =serde_yaml::to_string= output,
   which ends in a newline (=get_import.rs:56-57=).

Related, check while here: Rust's JSON format pretty-prints
(=serde_json::to_string_pretty= + =println!=, =get_import.rs:62-64=);
Haskell uses compact =Aeson.encode= plus a newline.

Confirmed 2026-11-16 by running both binaries on =x.yaml= containing
=a: 1=: Haskell =get-import x.yaml | od -c= shows =a :   1= with no
=\n=; =get-import --query a x.yaml= prints =a: 1= in Haskell and =1= in
Rust (=~/src/iidy/target/debug/iidy=).
