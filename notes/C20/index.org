Nothing bounds the work an input can cause. The C4 review showed a 380-byte
YAML file using nested aliases expanding to 19.7 MB of output at 253 MB of
memory (=src/Iidy/Yaml/Parser.hs= lines 73-74: =yAlias= returns the shared
node and =yAnchor= passes it through, with no count), and an import chain
running past 4,000 hops until killed (=pushImport= in
=src/Iidy/Yaml/Imports/Manifest.hs= lines 47-58 checks only for a repeated
location; it is called from =src/Iidy/Yaml/Engine.hs= lines 70 and 174).
Handlebars =pad= (=helperPad=, =doPad= in
=src/Iidy/Yaml/Handlebars/Helpers.hs= lines 169-188; the review quoted
line 174) builds =T.replicate= of an unchecked width, and it is the only
amplifying =replicate= in the Handlebars code. The HTTP loader
(=src/Iidy/Yaml/Imports/Loaders/Http.hs= lines 100-114, constants in
=src/Iidy/Constants.hs=) already caps the response body at
=httpMaxResponseBytes= (10 MB) and the wait for a response at
=httpTimeoutSeconds= (30 s), but nothing bounds total transfer time.

The Rust original has no such limits: =~/src/iidy/src/yaml/= has no depth,
alias or helper-size constant (only the circular-import check at
=engine.rs:82=); its YAML crate (=serde_yaml_ng=) may impose its own
recursion limit, which was not checked. The Haskell constants for existing
limits live in =Iidy.Constants=; the template size limits are in
=Iidy.Cfn.TemplateLoader= (=templateMaxBytes=, =s3TemplateMaxBytes=).
(The earlier Scope named =src/Iidy/Handlebars/=; the directory is
=src/Iidy/Yaml/Handlebars/=.) See
[[id:org:01a1e68e-1585-707c-91d5-94c92f017ed0][Low: no resource limits]].

the HTTP loader already has, and any change to behaviour below the limits.

Values (the review gives none; proposed 2026-11-16 for Tavis to confirm or
change before the card is assigned; each is a user-visible limit). They
are named constants in =Iidy.Constants=, with the reason recorded beside each:
- Alias expansion: at most 1,000,000 nodes after expanding aliases
  (scalars, sequences and mappings each count one). A 1 MB CloudFormation
  template (=s3TemplateMaxBytes= is 999,999) holds well under 500,000 nodes,
  so real documents have a wide margin. The review's bomb (five levels of
  fan-out 10, about 111,000 nodes) still loads under this limit, at the
  253 MB and 1.5 s the review measured; a sixth level (about 1.1 million
  nodes) is rejected. Tavis may prefer a lower figure such as 250,000.
- Import depth: at most 32 nested imports on one chain; at most 1,000
  imports resolved in one run. The review's chain ran past 4,000 hops;
  real projects nest a handful of levels.
- Helper output: no single Handlebars helper result longer than 1,048,576
  characters (1 MiB, the size of the largest deployable template); only
  =pad= can amplify today.
- HTTP import total time: 60 seconds from request to the end of the body,
  twice the existing 30 second wait for a response, enforced with
  =System.Timeout.timeout= around the whole fetch.
Rust has none of these, so each is a divergence to record.
