Reproduce with the example, record Rust's convention, fix the column, test.

Reproduced: =iidy-hs render= on the example printed =dup.yaml:4:2= with the
caret under the space before =c=.

Cause: a parse error's =Position= carries HsYAML's 0-based column
(=convertPos=, =src/Iidy/Yaml/Parser.hs:276=, despite the 1-based comment on
=posColumn= in =src/Iidy/Yaml/Location.hs=), and =formatParseErrorEnhanced=
(=src/Iidy/Yaml/Errors/Conversion.hs=) passed it straight to the display. The
only parse error that came out right was "unexpected field", through a
per-message =+1= in =adjustLocationForTag=
(=src/Iidy/Yaml/Errors/Conversion/Location.hs=).

Rust's convention is 1-based: =SourceLocation= displays =file:line:column=
as stored (=~/src/iidy/src/yaml/errors/enhanced.rs:37=); a syntax error
takes serde_yaml's =Location= (=~/src/iidy/src/yaml/errors/wrapper.rs:97=),
whose =from_mark= adds 1 to libyaml's 0-based column; a tag error's
location comes from =format_file_location=, =character + 1=
(=~/src/iidy/src/yaml/parsing/parser.rs:1947=); the caret column is
documented 1-based (=~/src/iidy/src/yaml/errors/display.rs:87=). Rust itself
accepts a repeated template key (see =DIVERGENCES.md=, "Duplicate Mapping
Keys"), so the example has no Rust output; its convention for parse errors
decides.

Fix: =formatParseErrorEnhanced= turns the column 1-based on entry, and the
"unexpected field" =+1= is dropped (it now double-counted). Tests in
=test/Test/ErrorContentTest.hs=, group "Parse error positions": "a repeated
nested key is shown at its 1-based column" (failed first with =t.yaml:4:2=)
and "an unexpected tag field is shown at its 1-based column" (pins
=tag-if-unknown-field.yaml:9:3=, which the entry change alone made =9:4=).
The =@ file:line:col= of every error fixture under
=test-fixtures/example-templates/errors/= matches the Rust binary except
=expand-missing-template= and =expand-parse-error=, where Rust prints no
location; that was so before this card.
