# Code Review Letter Grades -- 2026-03-01

Companion to [2026-03-01-fresh-review.md](2026-03-01-fresh-review.md).

| #  | Dimension                | Grade | Justification                                                                                                                                                                                          |
|----|--------------------------|-------|--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| 1  | Architecture & Design    | A     | Clean 86-module decomposition with clear boundaries (Yaml/, Cfn/, Output/, Aws/, Params/). Custom implementations for JMESPath, Handlebars, and JSON Schema are well-isolated. OValue for key-order preservation is a sound design decision. Only minor issue: some utility functions (percentEncode) live in StackOperations to avoid circular deps rather than in a shared module. |
| 2  | Code Quality             | A-    | Consistent style throughout: explicit type signatures, qualified imports, no orphan instances, good naming. A few blemishes: `init` (partial) in the emitter, `TE.decodeUtf8` (partial) in a few spots, and the `oValuesEqual` redundancy. The 869-line Resolver.hs is at the upper end of the 300-500 LOC guideline but is well-structured with clear section headers. |
| 3  | Correctness              | B+    | Core YAML preprocessing, CFN tag validation, and polling logic are solid. However, the silent env-map fallthrough (H-1) is a real user-facing bug, the SSM pagination truncation (C-1) is a data-loss issue, and the NTP underflow (H-3) is a latent correctness risk. The 49/49 error snapshot match and 37/37 render snapshot match demonstrate strong baseline correctness. |
| 4  | Security                 | A-    | Import type security gate enforces remote-base restrictions. Regex patterns are length-capped. HTTP responses are size-limited. Credentials are never written to disk. Circular import detection prevents infinite loops. Deductions: no S3 size limit (M-7), `defaultManagerSettings` lacks TLS for HTTPS imports (H-4), and no validation on NTP response plausibility (H-3). |
| 5  | Test Coverage            | A-    | 972 tests across 43 test modules with good breadth: snapshot comparisons, property tests, mock polling, fixture-driven error tests, renderer tests, and integration tests. Deductions: no tests for env-map error paths, no render-prefix template loader tests, no multi-page SSM pagination tests, and no NTP edge-case tests. The test infrastructure (builders for all 26 OutputData types) is excellent. |
| 6  | Rust Parity              | B+    | Field-for-field match on StackArgs (21 fields), terminal statuses (14, with documented provenance), and $envValues structure. Snapshot parity at 37/37 render + 49/49 error. Deductions: env-map error handling is silently permissive where Rust errors (H-1), HTTPS import support is broken where Rust works (H-4), and the `$envValues.region` default diverges from the new region-error behavior (M-5). Documented divergences (DIVERGENCES.md) are all intentional and reasonable. |
| 7  | Documentation            | A     | Module-level Haddock comments on nearly every file explaining purpose and spec references (RFC 4330, JMESPath spec, Handlebars guide, JSON Schema Draft 7). Terminal status provenance is documented with source-of-truth references. 13 PRD documents in docs/requirements/, 12 developer docs + 4 ADRs in docs/dev/. DIVERGENCES.md is thorough. Minor gap: some internal functions lack per-function docs. |
| 8  | Build & CI Hygiene       | A+    | Zero warnings with `-Wall -Wcompat`. Pre-commit hook enforces `-Werror` + full test pass on every commit. Nix flake for reproducible builds. Cabal deps are well-organized (library vs executable vs test). No unused deps confirmed (prettyprinter is used in Help.hs). 972 tests run in 0.23s. |
| 9  | Performance              | B     | Adequate for typical CloudFormation template sizes. `lookupO` is O(n) linear scan used in hot paths (M-1), `mergeOObjects` is O(n*m) (M-2), and HTTP Manager is recreated per import (H-4). The polling loop uses Set-based event dedup (O(log n) per event), and concurrent resource/changeset fetching is good. No lazy IO space leak risks identified. The custom SNTP client is lightweight. For the target workload (templates with tens to low hundreds of keys), these are acceptable but not optimal. |
| 10 | **Overall**              | **A-** | A well-executed port with strong architecture, clean builds, excellent documentation, and comprehensive tests. The critical SSM pagination bug and the env-map error-swallowing are the main blockers preventing an A. The codebase is production-ready after fixing C-1, H-1, H-2, and H-4. |
