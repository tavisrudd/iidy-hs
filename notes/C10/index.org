=constructCommandMetadata= (=src/Iidy/Cfn/CommandMetadata.hs=, line 40)
requires a full =StackArgs= value but reads exactly one field from it,
=saServiceRoleArn= (line 59, for =cmIamServiceRole=). Commands that have no
stack-args file pass a dummy =emptyStackArgs= (defined in
=src/Iidy/Cfn/Types.hs= line 114, with =saServiceRoleArn = Nothing=) from
=app/Main.hs= lines 125 (exec-changeset) and 169 (delete-stack). The other
caller is =src/Iidy/Cfn/Runner.hs= line 91, which passes the real parsed
=sa'=. =emptyStackArgs= is also used by =test/Test/GlobalConfigTest.hs=
and defined in =Types.hs=, so it stays.

Separately, the =naoFixtureSet= field (=src/Iidy/Cli.hs= line 92) is never
read or set. Looking further, the whole =NormalizedAwsOpts= record
(=Cli.hs= lines 87-93, exported at line 6) is never constructed or used
anywhere in =src/=, =app/= or =test/=, so the field is not the only dead
part. No test calls =constructCommandMetadata= (it makes an STS call);
=test/Test/Shared.hs= only builds =CommandMetadata= values directly.

Both items were left open by the March =constructCommandMetadata= refactor
handoff and the CLI utilities review; the C2 triage
([[file:../C2/report--handoff-triage.org][report]]) confirmed they are
still present.
