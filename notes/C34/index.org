iidy-hs accepts a mapping with a repeated key silently (the last value
wins), in templates, stack-args and imported YAML or JSON documents. Rust
rejects it (=Failed to parse YAML from F: duplicate entry with key "z"=,
and the same with "JSON" for =.json= files), and the TypeScript original's
js-yaml rejects duplicated mapping keys too. Found by
[[file:../C28/index.org][C28]] (see its question). Rust parity is the
project default and both originals agree, so this is a parity fix; it is
user-visible because templates with duplicate keys stop rendering.
