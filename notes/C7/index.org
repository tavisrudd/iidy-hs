=iidy get-import= loads one import location and prints it. In
=src/Iidy/GetImport.hs= (=runGetImport=) the import config is built with
=icAwsEnv = Nothing=, so every AWS-backed import type (=cfn:=, =ssm:=,
=ssm-path:=, =s3:=) fails with an import error. The Rust original builds an
AWS environment from the global options (profile, region, assume-role) in
=cfn/get_import.rs= around lines 15-27, so these imports work there. This is
a user-visible divergence from Rust. It was first flagged for =render= in
the March Gemini review of the render command; the C2 triage
([[file:../C2/report--handoff-triage.org][report]]) found =get-import= is
where the gap is real. Rust =render= also has no AWS environment, so
whether =render= should get one is a separate decision, not part of this card.

** Findings: Rust
:PROPERTIES:
:ID: org:01a1e680-4a8c-75fc-8330-371383410cd6
:ADDED: [2026-11-16 Mon 15:35]
:END:

=~/src/iidy/src/cfn/get_import.rs= (=get_import=) always calls
=config_from_normalized_opts= (=src/aws/mod.rs=) before loading anything,
then hands the =SdkConfig= to =ProductionImportLoader::with_aws_config=.
=config_from_normalized_opts= → =config_from_merged_settings= applies
=--region= and =--profile= to =aws_config::defaults(..)=, calls
=loader.load().await=, and wraps the credentials in an
=AssumeRoleProvider= when =--assume-role-arn= is set. It never resolves
credentials: the Rust SDK resolves them lazily at the first API call. It
returns =Ok= in practice, so the =format_aws_error= branch at config time is
effectively dead.

So construction is eager in code but lazy in effect: a =file:=, =env:= or
=random:= import never touches credentials or region.

Probed with the Rust debug binary (=~/src/iidy/target/debug/iidy=), under
=env -i HOME=<empty dir> AWS_EC2_METADATA_DISABLED=true= so no network call
could happen (the credential chain fails before any request is sent):

| Invocation                                      | stderr                                                                      | exit |
|-------------------------------------------------+-----------------------------------------------------------------------------+------|
| =get-import ssm:/foo= (region set, no creds)    | =Import error: Failed to fetch SSM parameter /foo: dispatch failure=       |    1 |
| =get-import cfn:output:mystack/Key= (same)      | =Import error: Failed to describe CloudFormation stack mystack: dispatch failure= | 1 |
| =get-import s3://b/k= (same)                    | =Import error: Failed to fetch S3 object s3://b/k: dispatch failure=       |    1 |
| =get-import ssm:/foo= (no region, no creds)     | =Import error: Failed to fetch SSM parameter /foo: dispatch failure=       |    1 |
| =get-import x.yaml= (no region, no creds)       | (none; prints =a: 1= on stdout)                                             |    0 |
| =--profile nope get-import x.yaml=              | (none; prints =a: 1=)                                                       |    0 |

Missing credentials therefore surface as an ordinary =Import error: ...=
line on stderr with exit code 1, only for AWS-backed import types. The
error text names the operation that failed; the SDK cause is the opaque
"dispatch failure". Note the =e.to_string().contains("AWS")= check in
=get_import= never fires for these messages, so =format_aws_error= is not
used either.

** Findings: Haskell
:PROPERTIES:
:ID: org:01a1e680-4a8c-75fc-8330-371242bb898d
:ADDED: [2026-11-16 Mon 15:35]
:END:

- =runGetImport= (=src/Iidy/GetImport.hs=) builds
  =ImportConfig { icAwsEnv = Nothing }=, so =withAwsEnv= in
  =src/Iidy/Yaml/Imports/Loaders/Dispatch.hs= always returns
  "AWS import type requires credentials and is not available in this
  context" for =cfn:=, =ssm:=, =ssm-path:=, =s3:=.
- The shared builder is =createAwsEnvFromSettings :: AwsSettings -> IO
  (Env, CredentialSourceStack)= in =src/Iidy/Aws/Config.hs=, fed by
  =cliToAwsSettings :: Cli -> AwsSettings= (=src/Iidy/Cli.hs=). That is how
  =Iidy.Cfn.Context.createContext= and the stack-args bootstrap in
  =Iidy.Cfn.Runner= build their env. It honours profile, region and
  assume-role, matching the Rust settings.
- Unlike Rust, it is eager in effect: =Amazonka.newEnv discover= resolves
  credentials up front and throws =AuthError= if none exist, and
  =resolveRegion= throws an =IOException= if no region is set. Calling it
  unconditionally would break =get-import file.yaml= on a machine without
  AWS config, which works in Rust.
- =runGetImport= only takes =GlobalOpts=; the AWS flags live in
  =cliAwsOpts=, so the call site in =app/Main.hs= has to pass
  =cliToAwsSettings cli= as well (one-line change).
- No mock =Amazonka.Env= existed in =test/=; existing AWS tests cover only
  pure parsing. =http-client= exposes =managerRawConnection= /
  =managerTlsConnection= and =makeConnection=
  (=Network.HTTP.Client.Internal=), which allow an in-process fake
  connection that never opens a socket.

** Design
:PROPERTIES:
:ID: org:01a1e680-4a8b-74d6-8de1-d9785fb28ff6
:ADDED: [2026-11-16 Mon 15:35]
:END:

1. Keep =createAwsEnvFromSettings= as the single env builder (no new
   builder code).
2. In =GetImport=, classify the location with =parseImportType=. Only when
   the type is =cfn:=, =ssm:=, =ssm-path:=, or =s3:= with remote imports
   allowed, run the env builder. This reproduces Rust's observable
   laziness: non-AWS imports never need credentials or a region.
3. If the builder throws (=AuthError=, =IOException= from the region
   check, or an amazonka =Error= from the STS assume-role call), print
   =Import error: <reason>= to stderr and exit 1, which is the same shape
   as Rust. The wording names the credential/region problem rather than
   Rust's "dispatch failure", which is more useful and still one
   =Import error:= line.
4. Split =runGetImport= into a thin wrapper and =runGetImportWith=, which
   takes the env provider as an =IO Env= action, so the test injects a mock
   env and also observes that the provider is not called for non-AWS
   imports.
5. Test helper =Test.MockAws=: an =Env= with static fake keys whose
   =http-client= =Manager= uses a fake connection. The fake reads the
   request bytes, routes on the =X-Amz-Target= header (SSM JSON protocol)
   or the =Action== form field (CloudFormation query protocol), and
   replies with a canned body from =test-fixtures/mock-aws/=.

** Implementation
:PROPERTIES:
:ID: org:01a1e684-179f-73e9-b757-3f4e72baa8ad
:ADDED: [2026-11-16 Mon 15:39]
:END:

- =src/Iidy/GetImport.hs=: =runGetImport= now takes the CLI
  =AwsSettings= and delegates to =runGetImportWith (fst <$>
  createAwsEnvFromSettings settings)=. =runGetImportWith= classifies the
  location with =parseImportType= and runs the env provider only when
  =needsAwsEnv= holds (=cfn:=, =ssm:=, =ssm-path:=, and =s3:= unless
  remote imports are blocked). =AuthError=, =IOException= (region check)
  and amazonka =Error= (STS assume-role) from the provider become one
  =Import error: <reason>= line on stderr and exit 1. No new env-building
  code: the builder is the same one the stack commands use.
- =app/Main.hs=: the call site passes =cliToAwsSettings cli= (one line).
- =test/Test/MockAws.hs=: reusable in-process mock =Amazonka.Env= (fake
  keys, us-east-1, =Amazonka.once=, http-client manager whose raw and TLS
  connection factories return a fake =Connection=; no socket is opened).
  Fixtures are looked up by =<host service>.<operation>.json|xml= under
  =test-fixtures/mock-aws/=; a missing fixture returns HTTP 400. Required
  adding =http-client= to the test-suite =build-depends= in
  =iidy-hs.cabal= (it is already a library dependency and in =flake.nix=).
- =test/Test/GetImportTest.hs= (group =GetImport=):
  - =ssm:/app/db-host= resolves to ="db.internal.example"= and the mock
    served =ssm.GetParameter.json=;
  - =cfn:output:network-stack/VpcId= resolves to ="vpc-0abc123"= via
    =cloudformation.DescribeStacks.xml=; =cfn:output:network-stack= returns
    the full outputs map;
  - a file import, an =env:= import, and an =s3:= import with remote
    imports blocked never call the env provider;
  - a provider throwing =CredentialChainExhausted= (=ssm:=, =cfn:=) or a
    region =IOException= (=ssm-path:=) gives exit 1 and no output;
  - =needsAwsEnv= over every =ImportType=, both remote settings.

because amazonka resolves credentials when the env is built rather than at
the first call.
