A stack-args file can compute its =Profile=, =Region= and =AssumeRoleARN=
from imports. The deploy commands build a first AWS environment from those
fields before preprocessing the file (=runCfnWithArgs= in
=src/Iidy/Cfn/Runner.hs= lines 64-70: =extractRawAwsFromFile=,
=mergeAwsSettings=, =createAwsEnvFromSettings=, every exception swallowed;
the raw field
reading is =resolveRawField= in =src/Iidy/Cfn/StackArgsLoader.hs= lines
199-208), so imports in the stack-args file run under the ambient
credentials and region rather than the ones the file finally names,
silently. The final environment is built later from the preprocessed values
(=Runner.hs= line 77, =loadStackArgs= lines 143-151 of the same loader).
The review quoted the loader as =src/Iidy/StackArgsLoader.hs=; the file is
=src/Iidy/Cfn/StackArgsLoader.hs=.

Rust does not have this feature: =load_stack_args=
(=~/src/iidy/src/cfn/stack_args.rs:181-262=) preprocesses with
=preprocess_yaml= first, whose =ProductionImportLoader::new()=
(=src/yaml/engine.rs:578=) has no AWS config, so an =ssm:=, =cfn:= or =s3:=
import in a stack-args file fails there with "AWS configuration required"
(=src/yaml/imports/loaders/mod.rs:72-93=); it reads
=Profile=, =Region= and =AssumeRoleARN= from the preprocessed value only.
Imports under a computed profile are therefore an iidy-hs extension, and
"matches Rust" cannot be the tie-breaker. See
[[id:org:01a1e68e-1585-707c-91d5-94cc843d0bd6][Medium: stack-args imports can run under different credentials]].

TypeScript (=~/src/iidy-js/src/cfn/loadStackArgs.ts:91-118=) reads
=Profile=, =AssumeRoleARN= and =Region= before preprocessing, accepts a plain
string or an environment map, throws "The X setting in stack-args.yaml must
be a plain string or an environment map of strings." for anything else (a
tag included), merges CLI overrides, then configures AWS before =transform=
runs the imports.

Reproduced on the branch base with the mock env (ghci script in the temp
dir): a file with =Profile: !$ prof= (=$defs= =prof: prod-account=),
=Region: "{{region}}"= and an =ssm:/app/db-host= import. The bootstrap
settings were =Profile= unset (ambient) and =Region= the literal string
="{{region}}"=; the mock served =ssm.GetParameter.json= under them; the final
merged settings were =Profile prod-account=, =Region eu-west-1=. So the
import ran under settings that differ from the final ones, silently.

Decision (Tavis, recorded in the gate): keep AWS imports in stack-args and
follow TypeScript. Fix shape, confirmed against TypeScript:
- A credential field read before preprocessing is either absent, a literal
  (plain string, or the current environment's plain-string entry in an
  environment map), or not plain (a tag, a handlebars template, an
  environment map lacking the environment or with a non-plain entry, any
  other node, or a document that is not a plain mapping).
- The import env is built lazily, at the first AWS import (classified by
  =needsAwsEnv=), from the CLI settings merged over the literal fields
  (=mergeAwsSettings=, unchanged). Before building it, a field that is not
  plain and not given on the command line refuses the import, so no AWS call
  runs under the wrong account. This is stricter than the gate's
  "compare after preprocessing" wording (which still lets the import run
  under ambient settings) and matches TypeScript, which refuses before any
  import. Literal fields pass through preprocessing unchanged, so no
  post-preprocessing comparison is needed.
- Narrower than TypeScript on purpose, to meet the gate's "computed =Region=
  with no AWS import loads as before": the refusal applies only when the file
  performs an AWS import. A file without AWS imports loads as today.
  Decision (Tavis, 2026-11-17): keep this narrower rule. Porting it to
  Rust is [[file:../C43/index.org][C43]].
- A factory failure at that point is reported with its cause instead of
  being swallowed.

Duplication found and how it is handled:
- The credential field names were spelled out in three places in
  =StackArgsLoader.hs= (=extractRawAwsFromAst=, =resolveEnvMaps=,
  =extractAwsSettings=); one owner, =CredentialField=, now lists them, with
  each field's key and CLI flag.
- AWS import classification: =needsAwsEnv= (=Iidy.GetImport=) is reused;
  =Iidy.GetImport= is outside the allowed paths, so it is imported, not moved.
- The env factory: production passes =createAwsEnvFromSettings=, as
  =runGetImport= does.
