Origin: C22 decision (Tavis, 2026-11-16). C22 makes iidy-hs reject a
stack-args file that has =CommandsBefore= for =create-stack=,
=update-stack=, =create-changeset= and =create-or-update=, because today the
field is parsed and silently never run. This card is the work to run it, as
Rust and TypeScript do, once there is a trust design.

What the originals do: Rust =~/src/iidy/src/cfn/stack_args.rs:277-313=
(with =process_commands_before= from line 493) and TypeScript
=~/src/iidy-js/src/cfn/loadStackArgs.ts:137-166= (with
=src/cfn/runCommandSet.ts:11-67=) run each command through =bash -c= in the
argsfile's directory, after expanding Handlebars with the =iidy= namespace,
only for the four operations above. Rust also prints each command, sets
=iidy_profile=, =iidy_region= and =iidy_environment=, defines three bash
helper functions and fails the load on a non-zero exit.

Why it needs a trust design: the command text is shell built from stack-args
values, and stack-args values can come from imports (including remote ones
allowed for local stack-args, under the trust model C15 added in
=docs/SECURITY.org=). Running that text through bash would let a remote or
computed document execute code on the operator's machine. Porting Rust
unchanged is not acceptable without deciding which sources may contribute to
a command.

Dependencies: C22 (the refusal this card removes) and the trust model of
C15.

[[file:report--commands-before-design.org][report--commands-before-design.org]]
compares Rust and iidy-js line by line (operations, command text source,
Handlebars context, shell, working directory, environment, helpers, stdin,
output, failure, import passes), lists which values can reach a shell and
their trust under C15, and gives four options with a recommendation. No
command-running code was written.

Existing owners found (duplication search): the literal-or-computed
classifier =readRawField= / =plainOrComputed= in
=src/Iidy/Cfn/StackArgs/Credentials.hs= (to extend to the
=CommandsBefore= list), and the shell runner =execShell= / =execDirect= in
=src/Iidy/Demo.hs:208-224= (to share, not copy).

Finding checked against the Rust binary: a ={{iidy.region}}= in a Rust
=CommandsBefore= entry fails the first preprocess ("Variable error:
'iidy.region' not found"), so the iidy-js =iidy.*= names do not work in
Rust today; Rust instead lets =$defs=, =$imports= and tag results into the
command text.

For Tavis: which option should C40 implement?
- A (recommended): only plain-string entries written in the local argsfile
  run, unexpanded; context reaches the command as environment variables
  (=iidy_command=, =iidy_environment=, =iidy_region=, =iidy_profile=,
  =iidy_stack_name=) taken only from the command line or literal fields;
  any templated, tagged, imported or merged entry is refused before
  anything runs; commands run before preprocessing so imports run once.
- B: A plus ={{iidy.command|environment|region|profile|stackName}}=
  placeholders, substituted only from command-line or literal values that
  match a safe character set; everything else refused.
- C: Rust parity, with computed command text shown and confirmed on a
  terminal or allowed by a new command-line flag.
- D: keep C22's refusal permanently.
Also to confirm with the choice: child stdout goes to stderr in
=--output-mode json=; stdin is =/dev/null=; output is streamed rather than
buffered.
