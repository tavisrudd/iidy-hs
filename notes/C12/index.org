=src/Iidy/Cfn/StackArgsLoader.hs= is about 730 lines (checked 2026-11-16),
above the project's guideline of roughly 300-500 lines per module. It mixes
loading, the credential-field reading added by
[[file:../C17/index.org][C17]], pure validation, and a walk over an aeson
=Value= to pull out fields, where direct field parsing would be shorter and
give better errors. Left open by the March post-review fixes (item 4C) and
the refactoring plan (phase 7); still true per the C2 triage
([[file:../C2/report--handoff-triage.org][report]]). Low priority: worth
doing when the module next needs changing.

Current layout of =StackArgsLoader.hs= (line numbers 2026-11-16, re-check):
- public API =loadStackArgs= (102) and =loadStackArgsWith= (129), which
  parses, preprocesses, resolves environment maps, injects =$envValues=,
  merges AWS settings and calls =valueToStackArgs=;
- credential fields (203-330): =CredentialField=, =RawField=,
  =readRawField=, =extractRawAwsFromAst=, =plainKeyLookup=;
- environment maps, environment tag, =$envValues= (332-427);
- AWS settings extraction and merging (428-468): =extractAwsSettings=,
  =mergeAwsSettings=, =mergeSentinel= and the two sentinels;
- unknown-key validation (469-544): =validTopLevelKeys=,
  =validateNoUnknownKeys=, =findSuggestion=;
- =valueToStackArgs= and the typed getters =getStr=, =getStrListValidated=,
  =getStrMapValidated=, =getInt=, =getBool=, =describeType=,
  =describeValue=, =parseOnFailure=, =parseCapabilities= (545-726).

Its importers are =src/Iidy/Cfn/StackArgsBootstrap.hs=,
=src/Iidy/Cfn/Runner.hs= (=LoadedStackArgs= only),
=test/Test/StackArgsLoaderTest.hs=, =test/Test/StackArgsBootstrapTest.hs=
and =test/Test/Phase14FixTest.hs= (=getStrMapValidated=). Keeping
=Iidy.Cfn.StackArgsLoader= as the public module that re-exports what they
import means none of them needs a new import.

Update 2026-11-16 (supervisor), from the C17 re-review: add a loader-level
seam and a test proving the C17 post-preprocessing backstop is wired in. The
re-review disabled the settings recording in
=StackArgsBootstrap.hs= (=writeIORef ranWith (Just importSettings)=, line 147
at the time of writing) and every bootstrap test still passed, because the
existing backstop tests call =importSettingsMismatch= directly and nothing
checks that =loadStackArgsBootstrapped= records the settings or compares
them. The recording is in =bootstrapLoader=; the comparison is in
=loadStackArgsBootstrapped= (lines 67-81).

Overlap: [[file:../C22/index.org][C22]] may add a refusal for =CommandsBefore=

Run this card first, or have C22 rebase onto it, so that edit lands in the
